# Start context dialog (retro skill, read only in the second or third retro)

Run it once with the user, one question at a time, plain text with options (again only if the user asks). Nothing is changed without the user's explicit yes. Start with `start-context.py new`: it lists skills/MCP servers not seen at the last offer (size >= 250 B, MCP size unknown counts); when it reports relevant news, steps 1 and 2 re-offer ALL items (old and new, also those already offered). After the user answered, run `start-context.py new --ack`.

1. *MCP servers* (`start-context.py mcp`, plus `claude mcp list`): first say in two or three plain sentences why this step exists, with the feeling behind it: everything the session carries at its start is paid for in every single session, forever; it is expensive in the long run and slows our work down (more to read, earlier handoffs, less room for the actual task). Then explain that every connected server adds tokens to every session; list them with a per-server recommendation (keep / deny, reason from the project's actual tool use). After the user's yes: `start-context.py deny-mcp NAME...` (default `.claude/settings.local.json`, this environment only; `--shared` writes the committed `.claude/settings.json` and blocks the server for everyone using it: say so). If a deny cannot be written (connectors, plugin servers, no file access) give the exact fallback from the `mcp` output. Undo: `undo-mcp`.
2. *Skills* (`start-context.py skills`): explain that each listed skill costs about 0.1-0.3k tokens per session, that switching off applies only to this environment (`.claude/settings.local.json`, `skillOverrides`) and can be switched on again (`skills-on NAME` or delete the entry). List the skills with a recommendation and reason (can go off / may become relevant soon), judged from the use counts and the retro data. For EVERY skill you recommend to switch off give a short summary (one or two sentences) of what it is for, so the user can decide without knowing it; open the skill's description if you are unsure. After the user's yes: `start-context.py skills-off NAME...` (both `name` and `plugin:name` forms work). Measured (2026-11-05, headless `claude -p`, Sonnet 5.5; `stem:` = skills of the STEM repo listed a second time as scoped entries): project skills and `stem:` duplicates showed about no effect, plugin skills (e.g. docx/pptx/xlsx) about -0.3k each: recommend those first.
3. *Measure and report*: `start-context.py measure` before and after (two runs each, noise about 0.4k) and the difference. Takes effect in the next session. Record decision, change and numbers in the retro notes; nothing is changed without the user's explicit yes.
