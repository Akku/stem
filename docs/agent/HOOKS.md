## Evidence per agent

- **Claude Code:** daily use.
- **Codex:** automated probe runs; hooks need the user's trust (bound to the file's hash); PreToolUse wiring observed in one CLI run (codex-cli 0.166.0, 2026-11-11: the large-read note reached the model, the deny guard stopped the command); the Codex app and the trust review itself are not covered.
- **DeutschlandGPT Code:** from its documentation only, no run recorded; the app documents no hooks.

## Project choices

A project switches a guard off in `docs/agent/stem-config.json`, which the scripts read at run time: `{"context_warning": false}`, `{"large_read_warning": false}`, `{"deny_guard": false}`. The hook entries stay as shipped. Never edit `.claude/settings.json` hooks or `.codex/hooks.json` for such a choice: Codex binds its trust to the file's hash and may block the edit.

## Changing the wiring

1. Edit `scripts/hooks/manifest.json` (new agent: a key under `agents`, a command template in `scripts/hooks-sync.py`, a `wiring` entry per guard).
2. Run `python3 scripts/hooks-sync.py`; `--check` must then pass.
3. Run the session-start and hook item of the port-check checklist (`docs/agent/PORT_CHECK.md`, C1) in that agent and record the result under `evidence`.
4. STEM itself: CHANGELOG entry with a `Migration:` line; a changed `.codex/hooks.json` makes Codex ask for trust again.
