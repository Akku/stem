# Changelog

Newest first. Projects read the entries newer than their `STEM_VERSION` (see `stem-update` skill). Each entry: what changed and who benefits; renames and removals get a `Migration:` line (what to rename or delete) that `stem-update` carries out.

## Unreleased
- **`AGENTS.md` budget 7.5 KB:** projects built on STEM almost always add project-specific rules, so the limit rises from 6.5 KB to 7.5 KB (7680 bytes; KB = 1024 bytes) in `.github/stem-check.py`, the `duplicates` topic of `docs/agent/retro-topics.json`, the retro skill and `CONTRIBUTING.md`. A project that wants a stricter limit overrides the `duplicates` topic in `docs/agent/retro-topics.local.json` (same id replaces; the file is project-owned and never overwritten by an update). Benefits: room for project rules without a retro signal. Migration: copy `docs/agent/retro-topics.json` and `.claude/skills/retro/full-stage.md`; keep your `retro-topics.local.json`; if you set the old 6656 limit by hand, change it to 7680 or leave it as a stricter project limit.
- **Decision records named ADR and checked:** `R-DECISION` now names the format (ADR, Nygard style, as produced by `backlog decision create`) with front matter `id`, `title`, `date`, `status` (`proposed`, `accepted`, `rejected`, `superseded by <id>`) and the sections Context, Decision, Consequences; `scripts/check-backlog.sh` reports a record without them or with another status. Benefits: decision records stay uniform and machine-checkable. Migration: copy `scripts/check-backlog.sh`; update `R-DECISION` in `docs/agent/OPERATING_MODEL.md`; fix reported records.
- **Parallel sessions: worktrees and explicit staging:** `R-STATE-COHERENCE` gets one bullet: parallel sessions on one repository use separate worktrees and stage explicit paths, never `git add -A` / `git add .`. Benefits: no session commits another session's half-finished files. Migration: update `R-STATE-COHERENCE` in `docs/agent/OPERATING_MODEL.md`.
- **Git guard rails:** new `commit-msg` hook enforces the commit message convention (first line `TASK-<n>: <summary>`; merge, revert, fixup, Release, Handoff, Initial commit and Set up exempt; rule in `R-STATE-COHERENCE`). `.claude/settings.json` additionally denies `git reset --hard`, `git clean -f`, `git checkout .`, `git restore .`, `git branch -D`, `git push --delete` and `--no-verify` on commit/push (the agent can no longer bypass the secret guard; you still can). `.gitignore` now lists `.agent-logs/`, `.claude/settings.local.json` and `.env*`. `bump-version.sh` hints `git tag -a` (annotated release tags). Benefits: traceable history, fewer destructive mistakes. Migration: copy `scripts/githooks/commit-msg` (executable), add the new deny rules to your `.claude/settings.json`, adjust unusual first lines of your own commit conventions.
- **`run.sh` prunes old logs:** after each run, logs in `.agent-logs/` older than `AGENT_LOG_KEEP_DAYS` (default 30, `0` keeps all) are deleted unless their file name appears under `backlog/` or `docs/` or in the paths of `AGENT_LOG_REFS`, so evidence cited in task notes survives. Benefits: the log folder no longer grows without bound. Migration: copy `scripts/run.sh`.

## 1.10.0
- **`context-report.py --since` for metrics after a change:** `--since`/`--until` take a local `YYYY-MM-DD[ HH:MM]` or any ISO time with `Z` or offset (also without seconds, e.g. `2026-11-03T15:10Z`), stop on unparsable input instead of silently filtering wrong, and the report prints the UTC window it used; the `retro` skill names `--since` for metrics that start after a change. Benefits: retro checks such as "no whole-file reads in the biggest carried results since change X" run without ad-hoc scripts, and a wrong cut-off is visible. Migration: copy `scripts/context-report.py` and `.claude/skills/retro/SKILL.md`.
- **Automatic hand-off to a fresh session inside a batch:** above the `R-BATCHING` context threshold, inside an approved batch, the agent writes the handoff at a task boundary and starts a fresh session itself (Claude desktop app: `start_session` with context `fresh`, never a fork, then `detach_session` so it does not report back; Codex app: new thread if possible; else headless `claude -p` / `codex exec` in the background; else the manual ready sentence). The old session stops; the new one never reports back unless it was started to report. `scripts/context-check.py` now also reads Codex session logs (registered as `UserPromptSubmit` hook in `.codex/hooks.json`) and has `--auto` for a task-end check, since hooks only fire on user prompts. Benefits: long batches continue without context rot and without a manual restart. Migration: copy `scripts/context-check.py`, `.codex/hooks.json` (keep project hooks), `.claude/skills/handoff/SKILL.md`, `docs/agent/CODEX.md`; update `R-BATCHING` in `docs/agent/OPERATING_MODEL.md` and core rule 9 in `AGENTS.md`.
- **Agent proposes missing tools:** new `R-DESIGN` bullet "Propose missing tools" (also one sentence in `AGENTS.md` core rule 4 "Evidence has limits" and a pointer in `testing-practices`): when work would clearly benefit from a tool or framework that is not set up (a manual browser or UI check repeated, recurring style fixes, no test runner for new logic), the agent proposes it unasked with reason, cost and a recommendation; installing stays the user's decision. Benefits: projects with many repeated manual checks get e.g. Playwright suggested without having to ask. Migration: update `R-DESIGN` in `docs/agent/OPERATING_MODEL.md`, copy `.claude/skills/testing-practices/SKILL.md`, add the sentence to rule 4 in `AGENTS.md`.
- **Pre-commit secret scan: fewer false positives:** the API key pattern in `scripts/githooks/pre-commit` now needs a non-alphanumeric character before `sk-`, so paths such as `task-15-profile-...` no longer block a commit; real keys still do. Migration: copy `scripts/githooks/pre-commit`.
- **Retro due threshold doubles after a quiet retro:** `scripts/session-start.sh` reports "RETRO DUE" after 8 done tasks, or after 16 when the newest `docs/agent/retro-runs/*.json` has `result` with `adopted` 0 and `open_signals` 0 (`RETRO_DUE_AFTER` still overrides; no run file or no result keeps 8). One sentence in `R-RETRO`. Benefits: fewer retro prompts in a stable project, reset to 8 as soon as a retro changes something. Migration: update `scripts/session-start.sh` and the `R-RETRO` rule in `docs/agent/OPERATING_MODEL.md`.
- **`context-report.py` cost window:** new `--until`, `--main-only` (no subagent transcripts or sidechain records) and `--cost` (one line: turns, tool_calls, cache_read, output); `--since`/`--until` accept UTC `YYYY-MM-DDTHH:MM:SSZ`. Benefits: the cost of one run (for example a retro) can be measured exactly instead of reconstructed. Migration: copy `scripts/context-report.py`.
- **`R-CONTEXT-OUTPUT` covers data exploration:** the existing large-output bullet now says to limit database rows, extracted text, XML/JSON and long CLI guides at the source (`LIMIT`, column list, `head`) or redirect them to a scratch file and read that by range. No new bullet, no cost claim (own measurement: such listings about 1.3 % of cache_read). Origin: field PR 13. Migration: update the bullet in `docs/agent/OPERATING_MODEL.md`.
- **Setup: backlog in the user's language and web view:** new setup question (step 1a-2) whether the user wants to read the backlog; if yes, the `Language` line in `AGENTS.md` makes task and doc titles, descriptions and acceptance criteria follow the user's language (notes, evidence lines and instruction files stay English), and setup ends by opening the Backlog.md web view (`backlog browser`) with the user and optionally configuring autostart (macOS launchd, Windows SessionStart hook; only after approval, with undo). The `AGENTS.md` budget rises from 6 KB to 6.5 KB (`stem-check.py`, `retro-topics.json`, retro audit text). Benefits: users who do not read English can follow the backlog. Migration: set the limits in `.github/stem-check.py` and `docs/agent/retro-topics.json` to 6656 bytes (existing projects need nothing else; the question only runs in new setups).
- **Three guardrails and two skill cleanups:** `R-DESIGN` adds "no speculative structure" (abstraction only for two real uses, no dependency for about 20 lines); `R-VERIFY` adds "never disable, skip or weaken a test to get green"; `testing-practices` asks TDD tests to fail first for the right reason and generalizes the one-off contrast/NaN lesson to "unparsable input must fail"; the `alignment` skill drops an origin sentence. Source: SPARC rules analysis and the 2026-11-02 prompt audit. Benefits: fewer over-built changes and fewer silently weakened checks. Migration: copy `.claude/skills/alignment/SKILL.md` and `.claude/skills/testing-practices/SKILL.md`; update `R-DESIGN` and `R-VERIFY` in `docs/agent/OPERATING_MODEL.md`.
- **Warning on whole-file reads of large files:** `scripts/large-read-warn.py` (PreToolUse hook on Read and Bash in `.claude/settings.json`) adds one line to the agent's context when a Read without offset/limit or a `cat FILE...` targets a text file over 8 KB (`LARGE_READ_BYTES`); `cat` is also found inside compound commands (`cd DIR && cat X; cat Y`, `&&`, `||`, `;`, `|`, newlines), relative paths follow `cd`, and a cat piped into another command or redirected stays silent. It warns, never blocks. Benefits: a whole script or skill read once is no longer carried unnoticed through 100+ turns. Migration: copy `scripts/large-read-warn.py` and add the `PreToolUse` entry from `.claude/settings.json` (keep project hooks).
